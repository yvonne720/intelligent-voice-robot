# 1.项目概述

## 1.1 项目背景

随着语音识别（ASR）、语音合成（TTS）和大语言模型（LLM）技术的快速发展，语音交互已成为人机交互的主流方式之一。本项目旨在开发一套全流程语音交互系统，实现 “语音输入 - 文字转换 - 智能回答 - 语音转换 - 语音输出” 的闭环，为用户提供自然、便捷的语音交互体验，适用于智能客服、智能家居控制、个人助理等场景。

## 1.2 项目目标

- 实现端到端语音交互：支持用户通过语音发起请求，系统通过语音反馈结果，无需手动输入文字。
- 保障交互连贯性：支持多轮对话，保留上下文信息，确保 AI 回答的相关性。
- 提供清晰的交互反馈：通过状态提示、文字记录等功能，让用户实时了解交互进度。
- 确保系统稳定性：通过 WebSocket 重连、数据校验等机制，降低交互中断风险。
- 简化数据存储：采用本地 SQLite 数据库存储历史记录，降低部署复杂度。

## 1.3 项目范围

- **核心功能**：语音采集与传输、语音转文字（ASR）、智能回答生成（LLM）、文字转语音（TTS）、语音播放、对话历史记录与管理。
- **用户端**：支持浏览器（PC 端）及移动设备浏览器，需适配麦克风和扬声器权限。
- **服务端**：处理 WebSocket 连接、调度 ASR/TTS/LLM 服务、管理对话上下文、通过 SQLite 存储历史记录。
- **第三方依赖**：可集成第三方 ASR（如阿里云、百度）、TTS（如腾讯云、科大讯飞）、LLM（如 GPT-3.5、LLaMA）服务，也支持自研服务接入。

# 2.需求分析

## 2.1功能需求

### 2.1.1 前端功能需求

| 模块           | 具体需求描述                                                 |
| -------------- | ------------------------------------------------------------ |
| 语音采集       | - 调用设备麦克风实时采集语音，支持实时流传输或按固定时长（如 300ms）分片传输。 - 提供明确的采集状态反馈（如 “正在录音...”“已停止录音”），支持用户手动点击按钮停止采集。 |
| WebSocket 管理 | - 与服务端建立、维持、断开 WebSocket 长连接；连接中断后 10 秒内自动重试，最多重试 5 次。 - 实现双向数据传输：上行发送语音分片，下行接收文字（ASR 结果、LLM 回答）和语音数据（TTS 结果）。 - 支持长语音数据的分片拼接（针对超过单分片长度的语音回复）。 |
| 语音播报       | - 接收服务端传回的语音数据后，调用设备扬声器实时播放。 - 支持播报控制：提供暂停、继续、停止功能，同步反馈 “正在播放”“播放暂停”“播放完成” 等状态。 |
| 交互界面       | - 核心入口：“按住说话” 按钮（长按开始录音，松开停止），辅助按钮（取消、重新开始）。 - 状态展示：实时显示当前流程状态（如 “正在识别语音”“AI 正在思考”“正在生成语音”）。 - 文字记录：左侧展示用户语音转文字内容，右侧展示 AI 回答文字，支持滚动查看。 - 历史记录：提供历史对话列表入口，点击可查看详情并回溯。 - AI 设置：支持对话前配置 AI 参数（如回答风格、语音类型、模型选择等）。 |

### 2.1.2 后端功能需求

| 模块               | 具体需求描述                                                 |
| ------------------ | ------------------------------------------------------------ |
| WebSocket 通信管理 | - 支持多用户同时连接，通过用户 ID（或会话 ID）区分连接，维护连接状态（在线 / 离线）。 - 实现数据路由：将前端上行语音数据转发至 ASR 处理模块，将 TTS 生成的语音数据转发至对应前端。 - 数据校验：校验语音数据格式（如是否为 PCM/MP3）、分片完整性（通过序号校验），拒绝无效数据并返回错误提示。 |
| ASR 服务调用与处理 | - 接收前端语音数据（完整流或分片拼接后），调用 ASR 服务（自研或第三方）进行语音转文字。 - 处理转换结果：成功则提取文本内容（context）；失败则生成错误标识（如 “ASR 转换失败，请重试”）。 - 关联会话上下文：按用户 ID + 会话 ID 存储 ASR 结果，确保多轮对话时上下文连续。 |
| LLM 调用与管理     | - 接收 ASR 模块传输的 context（或错误标识），若为有效文本则调用 LLM 服务生成回答。 - 上下文关联：向 LLM 传入当前会话的历史对话记录（从 SQLite 查询），确保多轮对话连贯性。 - 结果处理：提取 LLM 返回的有效文本作为 context_answer；若超时或返回无效内容，生成错误标识（如 “回答生成失败，请重试”）。 |
| 回答风格控制       | - 风格配置：支持按用户设置调整 LLM 参数（如温度值 0.3-0.9，值越低回答越固定，越高越灵活），适配 “简洁”“详细”“口语化” 等风格。 |
| TTS 服务调用与处理 | - 接收 LLM 模块传输的 context_answer（或错误标识），若为有效文本则调用 TTS 服务转换为语音。 - 结果处理：成功则提取语音数据，按前端兼容格式（如 MP3、PCM）处理；失败则生成错误标识（如 “TTS 转换失败，请重试”）。 - 语音分片：对长语音数据按固定长度分片，便于前端实时播放。 |
| 历史记录管理       | - 存储介质：本地 SQLite 数据库，无需额外部署数据库服务。 - 存储内容：每个对话记录包含用户 ID、会话 ID、时间戳、ASR 文本、AI 回答文本。 - 访问支持：提供按用户 ID、会话 ID、时间范围查询历史记录的接口。 |

## 2.2 非功能需求

- **性能**：端到端交互延迟≤3 秒（从用户停止录音到系统开始播放语音）；支持单用户连续 20 轮以上对话无异常。
- **兼容性**：前端兼容 Chrome 90+、Edge 90+、Safari 14 + 浏览器
- **稳定性**：WebSocket 连接成功率≥99%，重连成功率≥95%；服务调用失败时（如 ASR 超时），需返回明确错误提示。
- **安全性**：SQLite 数据库文件需设置访问权限，限制非授权读取。
- **可维护性**：前后端代码模块化设计，第三方服务接口通过配置文件管理，便于替换或升级。

## 3.2 前端设计

### 语音采集模块

- 技术依赖：浏览器`MediaDevices.getUserMedia()`API（获取麦克风权限）、`MediaRecorder`（录制音频）。
- 采集参数：采样率 16kHz（适配主流 ASR 服务）、单声道、PCM 格式（或实时转换为 MP3 以减少数据量）。
- 状态管理：通过`isRecording`变量标记采集状态，UI 同步显示对应文本（如按钮文字从 “按住说话” 变为 “正在录音...”）。

### WebSocket 管理模块

- 连接逻辑：初始化时创建`new WebSocket('wss://server-domain/socket.io')`，监听`onopen`/`onclose`/`onerror`事件。
- 重连机制：连接关闭且非主动断开时，启动定时器（10 秒间隔）重试连接，重试 5 次失败后提示用户 “连接失败，请刷新页面”。
- 数据传输：上行发送语音分片（二进制），下行接收 JSON 格式文字或二进制语音数据，通过`type`字段区分数据类型（如`type: 'asr'`表示 ASR 结果）。

### 语音播报模块

- 播放控制：基于`Audio`对象实现，通过`audio.pause()`/`audio.play()`/`audio.currentTime = 0`实现暂停、继续、停止功能。
- 分片拼接：接收长语音时，通过`audioQueue`数组缓存分片，累计 3 个分片后开始播放，避免卡顿。

### 交互界面模块

- 核心组件：
  - 操作区：固定在底部的 “按住说话” 按钮（长按触发`startRecording`，松开触发`stopRecording`）。
  - 状态区：位于按钮上方，显示当前流程状态（如 “正在识别语音...”）。
  - 对话区：占据屏幕主要区域，按时间顺序展示用户与 AI 的文字对话（左对齐用户内容，右对齐 AI 内容）。
  - 历史记录入口：顶部 “历史” 按钮，点击弹出历史会话列表（按日期分组）。
  - 设置面板：顶部 “设置” 按钮，展开后可选择 “回答风格”“语音类型” 等配置项。

## 3.3 后端设计

### WebSocket 通信模块

**功能**：管理客户端连接，转发语音数据至 ASR 模块，转发语音回复至前端。

- **连接管理**：接收前端发起的websocket连接，保持前后端的连接。
- **数据路由**：通过`type`字段区分数据类型（如`webrtc-offer`/`text`/`ping`），分发至对应模块。
- **重连机制**：客户端断开后，后端标记连接状态为 “离线”，等待客户端重连。

### LLM调用模块

**功能**：接收 ASR 文本，调用 LLM 生成回答，传入历史对话确保上下文关联。

- 实现Rag，从向量数据库中获取相关数据进行回答

### 数据库管理模块

**功能**：通过 SQLite 存储对话历史，支持写入与查询。

## 3.5 核心流程

1. **语音采集与传输**：用户长按前端按钮录音，前端每 100ms 发送语音分片至rustpbx。
2. **ASR 转换**：rustpbx调用 ASR 服务转为文字，发送文字至golang后端显示，golang后端转发信息到前端显示，并调用LLM。
3. **LLM 生成回答**：LLM 模块查询rag，添加上下文，调用 LLM 生成回答，发送文字至前端，并转发至 Rustpbx，Rustpbx调用TTS。
4. **TTS 转换与播放**：TTS 模块调用服务生成语音，发送至前端，前端实时播放最新语音。
5. **历史记录存储**：后端将对话数据插入 SQLite，支持后续查询。
